## Findings

### F01 — P1 — Selecting answers can omit the newest question and retain excluded answers

**Requirements:** G06, G07, G08, G11. **Class:** DEFECT. **Owner:** context assembly and revision reconciliation.

The response picker supplies assistant message IDs only. The backend applies selected-ID membership to every history role, including user prompts and tool messages. Separately, merging a saved revision copies old inclusion flags unchanged, so a later selection does not update existing answers.

**Witness:** Start with history u1 (user), a1 and a2 (assistant answers). Create the ordinary initial revision. Select only a1, append new user question u2, and call the real freezeSnapshot. The resulting message IDs are **u1,a1,a2**: a2 remains and u2 is absent. Returning to Include all still yields u1,a1,a2. With no prior revision, the selected-mode snapshot contains only a1, dropping both user messages.

**Expected:** This fixture should dispatch u1,a1,u2, exclude a2, and preserve both stored answers. Changing to Include all should restore applicable history. Every comparison participant should receive the same intended semantic context.

**Repair:** Apply response selection to the appropriate assistant responses; reconcile the active policy with saved revisions while preserving explicit context edits. Define one inclusion policy with clear precedence. Never silently exclude the new user prompt.

**Verification:** Assert exact message IDs and content in the dispatch snapshot before and after selection changes, including an existing revision, newly added user/tool messages, and two or more participants.

Sources: [assistant-only picker](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/web/app.js#L333-L374); [all-role membership check](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/server/src/contexts.js#L64-L94); [revision merge](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/server/src/contexts.js#L164-L174); [dispatch snapshot](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/server/src/harness.js#L86-L97).

### F02 — P1 — Delayed context dialogs can save into another conversation

**Requirements:** G07, G09, G11. **Class:** DEFECT. **Owner:** both frontend context dialogs and server context validation.

Two separate controls have the same navigation failure.

**Response-selection witness:** In conversation A, click Context and delay its detail response. Navigate to B, then release A's response. A's answers appear over B. Save sends PATCH /api/conversations/c2 with selectedMessageIds m1,m2 from A. The server accepts the policy without checking the selected messages' conversation.

**Full-editor witness:** Use empty conversations A and B with different projects. Delay A's context response, navigate to B, release A's response, then save. The browser sends A's project text to /api/conversations/c2/context-revisions. The exact server callback accepts it with **201**, labeling A's text as project:project-b because the editable block ID is merely project.

This changes B's effective context; it does not prove the underlying project record itself was overwritten. It can expose A's context to whichever provider B later uses.

**Repair:** Capture conversation/request identity before awaiting; discard responses superseded by navigation and bind saves to the original editor. Validate selected-message ownership and project/block identity. Preserve revision conflict checks.

**Verification:** Delay each dialog's read, navigate A→B, release it, then attempt Save. No state for B may change; stale A content must not appear as B's editable context.

Sources: [response selection](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/web/app.js#L333-L374); [editor binds ID after await](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/web/app.js#L1816-L1828); [editor save](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/web/app.js#L1895-L1911); [policy acceptance](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/server/src/index.js#L303-L317); [revision validation](https://github.com/The-Interdependency/a0/blob/de66778dd1d9073f6a8b3d532e73514868f94e3c/apps/server/src/index.js#L1092-L1119).

### F09 — P2 — New context and next-step cards have 1.10:1 text contrast

**Requirements:** G01, G03, G11, G12, G14. **Class:** DEFECT. **Owner:** shared CSS.

Nearly white text on nearly white cards makes important context difficult to read. **Repair and verification:** Use compatible foreground/background tokens for both rules, then check every affected surface.
